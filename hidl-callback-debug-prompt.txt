RumiTX 2030 v2.1 - HIDL Callback Debug Request

PROBLEM
The HIDL speak_enable callback never fires. The app gets stuck at RX_SUBMITTED, then times out after 30 seconds.

WHAT WORKS
- App installs and opens with the 2030 UI
- Helper daemon handshake: TCP open -> READY -> start OK -> serial OK
- Channel programming works (Beloit PD on 460.075 programmed successfully)
- PTT no longer crashes (threading fixed in v2.1)
- HIDL service found via HwBinder.getService()
- talkie_init() returns 0 (success)
- talkie_speak_enable() submits without error (oneway transaction 9)

WHAT DOESN'T WORK
- The ITalkiePortCallback.reportResults(int32) callback never fires
- After 30 seconds: RX_TIMEOUT
- No speaker chirp, no RX audio
- Squelch at 0 produces no static (speaker not initialized)

LOGS
See: https://drive.google.com/file/d/1ExW9_yJfXnfa4dUP4q2MqO2xanKLP-7c/view?usp=drivesdk

Key log lines show the coordinator stages:
- HELPER_CONNECTED, GREETING_READY, APP_START_ACK, SERIAL_SETUP_ACK, UART_OPEN all OK
- HIDL_FOUND, HIDL_INIT_ACK (returned 0) OK
- RX_SUBMITTED OK
- RX_TIMEOUT after 30s - callback missing

The previous v2.0 logs also showed:
- android.os.NetworkOnMainThreadException on PTT (FIXED in v2.1)
- Same RX_TIMEOUT on HIDL callback

TECHNICAL CONTEXT
- Transaction 9 (talkie_speak_enable) is oneway with an ITalkiePortCallback parameter
- The callback interface has one method: reportResults(int32)
- Current implementation creates a Binder for the callback via reflection
- The vendor service is vendor.hct.hardware.talkie@1.0-service (running, PID varies)
- SELinux is Permissive, so no denial blocks the callback

HYPOTHESES
1. The callback Binder isn't properly registered with the HwBinder framework - the vendor service can't find it to call back
2. The parcel format for the callback parameter is wrong - the service doesn't recognize it as a valid callback
3. The callback needs to be a specific subclass (e.g., extending a generated Stub class) rather than a raw Binder
4. There's a thread/looper issue - the callback needs a prepared Looper to receive the incoming transaction
5. The oneway flag isn't being set correctly on transaction 9

WHAT WE NEED
1. A working ITalkiePortCallback implementation that the vendor service can actually invoke
2. The callback must fire reportResults() when the speaker init completes
3. Detailed logging of the callback registration, parcel construction, and any incoming transactions

DELIVERABLE
A fixed APK where the HIDL callback fires and the speaker initializes. The app should show RX_CALLBACK (not RX_TIMEOUT) and the speaker should chirp.
