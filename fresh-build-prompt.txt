RumiTX 2030 - Fresh Build Request for DOOGEE S80

You are building a replacement for the stock Talkie app on the DOOGEE S80 (Android 8.1, MT6763T, DMR007 module at 57600 baud).

CURRENT STATE
- TX works: App -> TCP 127.0.0.1:45921 -> native daemon (/data/local/tmp/rumitx-ptt) -> HCT ioctl -> DMR007 -> RF. Verified with SDR.
- RX speaker init BROKEN after phone reboot. Before reboot, speaker chirped and RX static was audible. After reboot, no chirp.
- Root cause: The HIDL service vendor.hct.hardware.talkie@1.0::ITalkiePort needs proper initialization (talkie_init, talkie_speak_enable), not just service discovery via getService().
- The app currently does getService() which returns a valid binder but doesn't initialize hardware.
- Direct transact() calls for init (txn 1) and app_start (txn 3) return 0 but don't produce the chirp.
- Astra's analysis: helper daemon owns APP_START via ioctl. HIDL should do init() then speak_enable() (oneway, txn 9 with callback), WITHOUT a second app_start.

WHAT TO BUILD
A fresh APK that:
1. On startup, connects to helper daemon (TCP 127.0.0.1:45921, expects READY, sends "start", sends "serial")
2. After helper is ready, initializes HIDL speaker via proper sequence:
   a. HwBinder.getService("vendor.hct.hardware.talkie@1.0::ITalkiePort", "default")
   b. transact(1) for talkie_init - log return value
   c. transact(9, oneway) for talkie_speak_enable with callback binder
   d. Wait for reportResults callback (30s timeout)
   e. Do NOT call transact(3) app_start - helper already did APP_START via ioctl

4. Keeps existing TX path (PTT button, daemon commands) unchanged
5. Keeps existing volume keys (24/25) -> DMR007 volume frame
6. Keeps existing channel programming via serial

CRITICAL: The speak_enable callback binder is the hard part. Transaction 9 is oneway and takes an ITalkiePortCallback. You need to create a Binder object that implements the callback interface and pass it in the request parcel. Without this, the vendor service can't report results.
