RumiTX v2.2 TX REGRESSION - Fix only this, change nothing else.

PROBLEM
PTT no longer produces RF. The daemon receives the key-down ioctl and reports success (keyed=true, error=null), but SDR confirms zero RF output on the programmed frequency.

WHAT BROKE
v2.1 fixed a NetworkOnMainThreadException by moving the PTT TCP call off the UI thread. That fix broke TX. In the working build, RadioController.pttDown() did two things in order:
1. Sent a DMR007 serial frame via UART (to key the module's transmitter)
2. Sent "down 0" via TCP to the daemon (for the HCT ioctl)

The v2.2 threading change likely broke step 1 or the ordering. The ioctl succeeds but the module never transmits.

EVIDENCE
- ADB logs show "RumiTX-PTT: keyed=true error=null" three times (PTT pressed 3x, ~5 sec each)
- SDR (RTL-SDR, rtl_power) monitored 420.4200 MHz analog for 50 seconds during those transmissions
- Peak signal: 9.1 dB at 420.2081 MHz (background, not Doug)
- Power at 420.4200 MHz: nothing above -15 dB noise floor during any TX
- Earlier today (pre-v2.2), same SDR setup detected 7.3 dB increase on 446.5555 during TX
- Channel was programmed and active (screenshot confirms 420.4200 ANALOG selected)
- RX works fine (HIDL callback fires, audio heard) - do not touch RX

FIX REQUIRED
Restore the TX path so that PTT produces RF again:
1. Ensure pttDown() sends the DMR007 TX frame via UART BEFORE the daemon "down" command
2. Keep the network call off the UI thread (don't reintroduce the crash)
3. Verify the frame is actually written to /dev/ttyMT1 and the module ACKs it

DO NOT CHANGE
- HIDL RX init (working)
- Channel programming (working)
- Volume control (working)
- UI layout (working)
- Discovery mode (working)
- Anything else

TEST
After fix: PTT on 420.4200 analog should produce SDR-detectable RF carrier. The TX beep Doug hears is not sufficient - we need actual RF output confirmed by SDR.

Return only a fixed APK. Minimize changes.
