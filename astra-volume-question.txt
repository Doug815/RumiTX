RumiTX 2030 - RX volume control question.

STATUS
HIDL RX audio is WORKING. Our app accesses vendor.hct.hardware.talkie@1.0::ITalkiePort via android.os.HwBinder reflection. Speaker initializes with the stock-app chirp, RX static is audible. TX also works.

PROBLEM
RX speaker volume is at full blast and can't be adjusted. The stock app lets you use the side volume buttons (Android keycodes 24/25) to control it.

QUESTION
How does the stock HcTTalkie app control RX speaker volume?

Specifically:
1. Does it use Android AudioManager (STREAM_MUSIC or STREAM_VOICE_CALL) with the standard volume keys?
2. Is there a HIDL method on ITalkiePort for volume/gain that we missed? (Our transaction map has 1=init, 2=deinit, 3=app_start, 4=app_exit, 5=ppt_down, 6=ppt_up, 7=speak_disable, 8=update, 9=speak_enable. Is there a volume method we haven't found?)
3. Does it control the amplifier directly via a different path (e.g., tinymix, ALSA, or a vendor audio HAL)?
4. In the stock vdex, what does the volume key handler (keycodes 24/25) actually call?

We need to know the exact mechanism so we can implement volume control in RumiTX. The goal is side-button volume that adjusts the RX speaker without affecting TX.
